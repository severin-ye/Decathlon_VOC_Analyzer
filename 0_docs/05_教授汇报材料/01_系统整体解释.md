# Decathlon VOC Analyzer — 系统整体解释
# Decathlon VOC Analyzer — 시스템 전체 설명

---

## 程序是做什么的 / 이 프로그램은 무엇을 하는가

**Decathlon VOC Analyzer** 是一个**证据驱动的多模态 VOC（Voice of Customer）分析系统**。它不满足于仅对用户评论做情感分类或简单的词频统计，而是将商品描述文本、商品图片和用户评论三者对齐，生成一份可追溯、可验证的结构化分析报告。

**Decathlon VOC Analyzer**는 **증거 기반 멀티모달 VOC(Voice of Customer) 분석 시스템**입니다. 단순한 감성 분류나 키워드 빈도 분석에 그치지 않고, 상품 설명 텍스트, 상품 이미지, 사용자 리뷰를 정렬하여 추적 가능하고 검증 가능한 구조화된 분석 보고서를 생성합니다.

---

## 输入是什么 / 입력은 무엇인가

每个商品的文件夹包含三个部分：

```
product.json     → 商品名称、描述、规格、变体信息
reviews.json     → 用户评论（含星级评分）
images/          → 商品图片（多角度/多变体）
```

각 상품 폴더는 다음 세 가지로 구성됩니다:

```
product.json     → 상품명, 설명, 규격, 변형 정보
reviews.json     → 사용자 리뷰 (별점 포함)
images/          → 상품 이미지 (다양한 각도/변형)
```

---

## 输出是什么 / 출력은 무엇인가

系统生成以下产物：

| 产物 | 说明 |
|------|------|
| **结构化分析报告** (`4_reports/`) | JSON 格式，包含 strengths、weaknesses、controversies、evidence gaps、suggestions |
| **HTML 报告** (`6_html/`) | 浏览器可直接查看的人类可读报告 |
| **证据归因** | 每个 claim 绑定到具体的评论文本、商品文本或商品图片证据 |
| **运行清单** (`7_manifests/`) | 记录运行参数、中间产物路径，支持重现和错误追踪 |
| **回放侧边车** (`5_replay/`) | 可审计的运行记录，支持人工修正后重新分析 |

시스템은 다음과 같은 산출물을 생성합니다:

| 산출물 | 설명 |
|------|------|
| **구조화된 분석 보고서** (`4_reports/`) | JSON 형식 — 강점, 약점, 논란, 증거 공백, 개선 제안 포함 |
| **HTML 보고서** (`6_html/`) | 브라우저에서 바로 볼 수 있는 사람이 읽기 쉬운 보고서 |
| **증거 귀속** | 각 claim을 특정 리뷰 텍스트, 상품 텍스트, 상품 이미지 증거에 연결 |
| **실행 매니페스트** (`7_manifests/`) | 실행 파라미터와 중간 산출물 경로를 기록하여 재현성과 오류 추적 지원 |
| **리플레이 사이드카** (`5_replay/`) | 감사 가능한 실행 기록, 사람 피드백을 통한 재분석 지원 |

## 核心流程（四级流水线） / 핵심 흐름 (4단계 파이프라인)

```
原始商品文件夹
  product.json + reviews.json + images/
         |
         v
┌──────────────────────────────────────────────────┐
│ Stage 1. 商品证据标准化  (상품 증거 표준화)         │
│ → 将商品文本、图片、图片区域、评论转为              │
│   带稳定 ID 的 ProductEvidencePackage             │
│ → 텍스트/이미지/리뷰에 안정적인 ID 부여             │
├──────────────────────────────────────────────────┤
│ Stage 2. VOC 需求建模   (VOC 수요 모델링)          │
│ → 评论过滤 → 星级感知抽样 → 方面(Aspect)提取 → 去重│
│ → 리뷰 필터링 → 별점 인지 샘플링 → 측면 추출 → 중복 제거 │
├──────────────────────────────────────────────────┤
│ Stage 3. 问题导向多模态检索 (질문 기반 멀티모달 검색)│
│ → 方面 → 证据问题规划                              │
│ → 文本路径召回 + 图像路径召回                      │
│ → 双路结果合并 → 重排序 → 缓存                     │
│ → 측면 → 증거 질문 계획                             │
│ → 텍스트 경로 회수 + 이미지 경로 회수                │
│ → 듀얼 경로 병합 → 재순위화 → 캐싱                │
├──────────────────────────────────────────────────┤
│ Stage 4. 证据约束报告生成 (증거 제약 보고서 생성)     │
│ → 结构化 VOC 报告生成                              │
│ → Claim 级证据归因 (supported/partial/unsupported) │
│ → 回放侧边车 → HTML 导出 → Manifest 写入          │
│ → 구조화 VOC 보고서 생성                           │
│ → Claim 단위 증거 귀속                            │
│ → 리플레이 사이드카 → HTML 내보내기 → 매니페스트   │
└──────────────────────────────────────────────────┘
```

### Stage 1 — 商品证据标准化 / 상품 증거 표준화

将分散的商品信息（标题、描述、规格、图片、评论）统一为 `ProductEvidencePackage`。产品文本按段落拆分为 text block，每张图片按变体归类并分配稳定 ID。所有 ID 在后续阶段中保持不变，确保最终报告中每个 claim 都能追溯到具体证据。

흩어져 있는 상품 정보(제목, 설명, 규격, 이미지, 리뷰)를 통일된 `ProductEvidencePackage`로 표준화합니다. 상품 텍스트는 단락별 text block으로 분할되고, 각 이미지는 변형별로 분류되어 안정적인 ID가 할당됩니다. 이후 단계에서도 ID가 유지되므로, 최종 보고서의 모든 claim이 어떤 증거에서 나왔는지 추적할 수 있습니다.

### Stage 2 — VOC 需求建模 / VOC 수요 모델링

- **评论过滤**：排除无信息量的评论（如 "ok"、"good"、"great"）
- **星级感知抽样**：默认使用 `problem_first` 策略，1~5 星按 30%/25%/20%/15%/10% 配比，优先保留低分评论中的问题信号
- **方面提取**：从评论中提取属性、情感、意见、使用场景等结构化 Aspect 对象
- **去重**：合并语义重复的方面

- **리뷰 필터링**: 정보량이 적은 리뷰("ok", "good", "great" 등) 제외
- **별점 인지 샘플링**: 기본 `problem_first` 전략 사용 — 1~5점 리뷰를 30%/25%/20%/15%/10% 비율로 배분, 저평점 리뷰의 문제 신호를 우선 보존
- **측면 추출**: 리뷰에서 속성, 감성, 의견, 사용 장면 등 구조화된 Aspect 객체 추출
- **중복 제거**: 의미적으로 중복된 측면 통합

### Stage 3 — 问题导向多模态检索 / 질문 기반 멀티모달 검색

这是本系统区别于普通分析器的**核心差异**。

- **问题规划 (Question Planning)**：每个评论方面被分解为三种证据意图：
  1. **文本支持** — 商品描述/规格是否支持该意见？
  2. **视觉确认** — 商品图片是否展示相关特征？
  3. **跨模态解析** — 文本和图像解释是否一致？
- **双路召回**：文本路径（商品描述文本）和图像路径（商品图片）独立检索
- **跨模态重排序**：使用证据评分公式 S(a,e) = λₜRₜ + λᵥRᵥ + λ꜀C 对候选证据排序
- **检索缓存**：相同查询条件下复用结果，减少冗余 LLM 调用

이것이 본 시스템을 일반 분석기와 구별하는 **핵심 차이점**입니다.

- **질문 계획 (Question Planning)**: 각 리뷰 측면은 세 가지 증거 의도로 분해됨:
  1. **텍스트 지지** — 상품 설명/규격이 해당 의견을 뒷받침하는가?
  2. **시각 확인** — 상품 이미지가 관련 특징을 보여주는가?
  3. **크로스모달 해석** — 텍스트와 이미지의 해석이 일치하는가?
- **듀얼 경로 회수**: 텍스트 경로와 이미지 경로에서 독립적으로 검색
- **크로스모달 재순위화**: 증거 점수 공식 S(a,e) = λₜRₜ + λᵥRᵥ + λ꜀C 로 후보 증거 정렬
- **검색 캐시**: 동일 쿼리 조건에서 결과를 재사용하여 중복 LLM 호출 감소

### Stage 4 — 证据约束报告生成 / 증거 제약 보고서 생성

- 生成结构化 VOC 报告（strengths, weaknesses, controversies, evidence gaps, suggestions）
- 每个 claim 绑定到具体证据（review evidence / product text evidence / product image evidence）
- 标记证据状态：supported / partial / unsupported / contradicted
- 导出 HTML 报告
- 写入运行清单（manifest）供后续审计

- 구조화된 VOC 보고서 생성 (강점, 약점, 논란, 증거 공백, 개선 제안)
- 각 claim을 구체적 증거에 바인딩 (리뷰 증거 / 상품 텍스트 증거 / 상품 이미지 증거)
- 증거 상태 표시: supported / partial / unsupported / contradicted
- HTML 보고서 내보내기
- 실행 매니페스트 기록 (향후 감사용)

## 核心技术特性 / 핵심 기술 특징

### 1. 证据驱动而非纯摘要 / 증거 기반, 단순 요약이 아님

传统分析器直接对评论做摘要或情感分类。本系统不直接输出结论——它先检索商品证据来验证评论意见，再生成有证据支持的结论。未找到证据的意见会被标记为 **evidence gap**。

기존 분석기는 리뷰를 요약하거나 감성을 분류하는 데 그칩니다. 본 시스템은 바로 결론을 내리지 않고, 먼저 상품 증거를 검색해 리뷰 의견을 검증한 후 증거가 뒷받침하는 결론을 생성합니다. 증거가 발견되지 않은 의견은 **evidence gap**으로 명시적으로 표시됩니다.

### 2. 多模态双路检索 / 멀티모달 듀얼 경로 검색

文本和图片不在同一向量空间中混排，而是独立召回后通过跨模态一致性约束结合。这避免了单一模态的盲区。

텍스트와 이미지를 동일한 벡터 공간에서 단순 혼합하지 않고, 독립적으로 회수한 후 크로스모달 일관성 제약을 통해 결합합니다. 이로써 단일 모달리티의 맹점을 피할 수 있습니다.

### 3. 全链路可追溯 / 전체 경로 추적 가능

从原始评论 → Aspect → Question → Retrieved Evidence → Claim → Attribution 全链路 ID 追踪。任何一个 claim 都能反查到"出自哪条评论 + 哪个商品文本 + 哪张图片"。

원본 리뷰 → Aspect → Question → Retrieved Evidence → Claim → Attribution 전 경로 ID 추적. 모든 claim이 "어느 리뷰 + 어느 상품 텍스트 + 어느 이미지"에서 왔는지 역추적 가능합니다.

### 4. 模块化后端切换 / 모듈화 백엔드 전환

所有 AI 组件可独立切换模式：

| 组件 | 远程 API 模式 | 本地模型模式 |
|------|-------------|------------|
| LLM 生成 | qwen-plus / DeepSeek-V3 | - |
| 文本嵌入 | text-embedding-v4 | Qwen3-Embedding-0.6B |
| 图像嵌入 | CLIP ViT-B/32 | Qwen3-VL |
| 文本重排 | gte-rerank-v2 | Qwen3-Reranker-0.6B |
| 多模态重排 | qwen-vl-max | Qwen3-VL-2B-Instruct |
| 向量存储 | 本地 JSON 索引 | Qdrant |

## 技术栈 / 기술 스택

- **语言**：Python ≥3.11
- **编排**：LangGraph（多步骤工作流）
- **API**：FastAPI（7 个 REST 端点）
- **数据模型**：Pydantic（强类型 Schema 约束）
- **LLM 网关**：OpenAI 兼容接口，支持多供应商
- **向量存储**：本地 JSON 索引 / Qdrant
- **嵌入**：CLIP（图像）、text-embedding（文本）
- **本地推理**：OpenVINO（Qwen3 系列模型）
- **测试**：pytest（166 个自动化测试通过）

## 为什么不是普通情感分析器 / 왜 일반 감성 분석기가 아닌가

| 对比维度 | 普通情感/摘要分析器 | 本系统 |
|----------|-------------------|--------|
| 분석 대상 | 리뷰 텍스트만 | 리뷰 + 상품 설명 + 상품 이미지 |
| 처리 방식 | 단일 단계 요약 | 4단계 분리 파이프라인 |
| 증거 연결 | 불분명 | Claim 단위 증거 귀속 |
| 오류 추적 | 어려움 | 단계별 ID 추적 가능 |
| 멀티모달 | 없음 | 텍스트+이미지 듀얼 경로 |
| 결과 검토 | 낮음 | feedback/replay 루프 지원 |
| 출력 | 텍스트 요약 | 구조화 VOC 보고서 + HTML |

> 이 시스템은 리뷰를 "요약"하는 것이 아니라, 리뷰 의견과 상품 증거 사이의 **연결 관계**를 단계별 객체와 링크로 보존합니다.

.venv/bin/python 04_scripts/run_workflow.py \
  --category backpack \
  --product-id backpack_010 \
  --R_5 \
  --no-llm \
  --retrieval-backend local \
  --export-html \
  --write-manifest

# 完整流水线
.venv/bin/python 04_scripts/run_workflow.py \
  --category backpack \
  --product-id backpack_010 \

uvicorn decathlon_voc_analyzer.app.api.main:app --reload
