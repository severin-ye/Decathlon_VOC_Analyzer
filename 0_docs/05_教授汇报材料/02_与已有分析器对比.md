# 与已有分析器的区别 / 기존 분석기와의 차이

---

## 概述 / 개요

本系统与三类已有方法存在本质区别：(1) 传统评论摘要器、(2) 基于方面的情感分析 (ABSA) 工具、(3) 一般 RAG 系统。以下逐一进行定性说明，不涉及具体实验数值。

본 시스템은 세 가지 기존 방법과 본질적인 차이가 있습니다: (1) 전통적 리뷰 요약기, (2) ABSA(측면 기반 감성 분석) 도구, (3) 일반 RAG 시스템. 아래에서 각각 정성적으로 설명합니다. 실험 수치는 포함하지 않습니다.

---

## 核心差异总表 / 핵심 차이 요약표

| 구분 | 전통적 리뷰 요약기 | ABSA 기반 분석기 | 제안 시스템 (本系统) |
|------|-------------------|-----------------|-------------------|
| **처리 단위** | 리뷰 전체 요약 | aspect-sentiment pair | 증거 객체, 리뷰 측면, 질의, claim |
| **处理单元** | 评论文本整体摘要 | 方面-情感对 | 证据对象、评论方面、查询、Claim |
| **상품 증거 사용** | 제한적 또는 없음 | 대체로 없음 | 상품 텍스트·이미지 증거를 함께 검색 |
| **商品证据使用** | 有限或无 | 通常无 | 同时检索商品文本和图片证据 |
| **부정 리뷰 활용** | 비명시적 | 감성 태도만 반영 | 원시 리뷰와 별점을 모두 보존하고 문제 우선 샘플링 적용 |
| **负面评论利用** | 不明确 | 仅反映情感极性 | 保留全部原始评论并采用问题优先抽样 |
| **멀티모달 처리** | 거의 없음 | 없음 | 텍스트/이미지 분리 검색 및 재순위 |
| **多模态处理** | 几乎没有 | 无 | 文本/图像独立检索与重排 |
| **결과 검토 가능성** | 낮음 | 중간 | claim 단위 귀속과 evidence gap 제공 |
| **结果可审核性** | 低 | 中等 | Claim 级归因 + Evidence Gap 标注 |

## 详细对比 / 상세 비교

### 一、vs 传统评论摘要器 / 전통적 리뷰 요약기 vs 제안 시스템

**传统摘要器的工作方式**：
- 将商品所有评论拼接后送入 LLM 生成一段摘要文本
- 输出为自然语言段落，无结构化约束
- **无法追溯**：读者无法知道"这条结论来自哪条评论、哪个商品描述、哪张图片"

**전통적 요약기의 작동 방식**:
- 모든 리뷰를 이어 붙여 LLM에 입력하고 요약 문단을 생성
- 출력은 개방형 자연어, 구조화 제약 없음
- **추적 불가**: "이 결론이 어느 리뷰, 어느 상품 설명, 어느 이미지에서 나왔는지" 알 수 없음

**本系统的区别（定性）**：
1. **不直接摘要**：先提取评论方面，再为每个方面规划三种证据意图的检索问题（文本支持 / 视觉确认 / 跨模态解析），然后检索商品证据
2. **证据约束生成**：报告中的每个 claim 必须关联到具体证据对象（review block / product text block / image），生成过程受证据约束而非自由生成
3. **证据空白处理**：无法找到足够证据支持的意见不强行编造，而是标记为 `evidence_gap`
4. **全链路可追溯**：从 final claim → 检索证据 → 问题规划 → 评论方面 → 原始评论，每一步都有稳定 ID 追踪

**본 시스템의 차이점 (정성적)**:
1. **직접 요약 안 함**: 먼저 리뷰 측면을 추출하고, 각 측면에 대해 세 가지 증거 의도(텍스트 지지/시각 확인/크로스모달 해석)의 검색 질문을 계획한 후 상품 증거를 검색
2. **증거 제약 생성**: 보고서의 각 claim이 구체적 증거 객체에 연결되어야 하며, 생성 과정이 증거에 의해 제약됨(자유 생성이 아님)
3. **증거 공백 처리**: 충분한 증거가 발견되지 않은 의견은 억지로 생성하지 않고 `evidence_gap`으로 표시
4. **전체 경로 추적 가능**: 최종 claim → 검색된 증거 → 질문 계획 → 리뷰 측면 → 원본 리뷰, 각 단계에 안정적인 ID로 추적

### 二、vs ABSA (Aspect-Based Sentiment Analysis) / ABSA vs 제안 시스템

**ABSA 的工作方式**：
- 从评论中提取 (方面, 情感极性) 对，如 "(容量, 负面)"
- 统计正面/负面方面分布
- 通常仅分析评论文本，不使用商品信息
- 输出为 aspect-polarity 矩阵或分类标签

**ABSA의 작동 방식**:
- 리뷰에서 (측면, 감성 극성) 쌍 추출, 예: "(용량, 부정)"
- 긍정/부정 측면 분포 통계
- 대체로 리뷰 텍스트만 분석, 상품 정보 사용 안 함
- 출력은 aspect-polarity 행렬 또는 분류 라벨

**本系统的区别（定性）**：
1. **不止于情感标签**：ABSA 输出 "(容量, 负面)"，本系统追问"**为什么**用户觉得容量小？商品描述是否标明容量？图片是否展示了内部空间？"
2. **商品证据交叉验证**：ABSA 仅分析评论，本系统用商品描述和图片来支持或纠正评论意见
3. **问题导向而非标签导向**：ABSA 输出分类标签，本系统为每个方面生成多模态检索问题
4. **结构化报告而非分类矩阵**：输出完整的 VOC 报告（优点/缺点/争议/建议/证据空白），而非 aspect-polarity 表格

**본 시스템의 차이점 (정성적)**:
1. **감성 라벨을 넘어서**: ABSA는 "(용량, 부정)"을 출력하지만, 본 시스템은 "**왜** 사용자가 용량이 작다고 느끼는가? 상품 설명에 용량이 명시되어 있는가? 이미지가 남부 공간을 보여주는가?"를 추적
2. **상품 증거 교차 검증**: ABSA는 리뷰만 분석하는 것과 달리, 본 시스템은 상품 설명과 이미지로 리뷰 의견을 뒷받침하거나 수정
3. **질문 기반, 라벨 기반이 아님**: ABSA는 분류 라벨을 출력하지만, 본 시스템은 각 측면에 대해 멀티모달 검색 질문을 생성
4. **구조화 보고서, 분류 행렬이 아님**: 완전한 VOC 보고서(강점/약점/논란/제안/증거 공백)를 출력, aspect-polarity 표가 아님

### 三、vs 一般 RAG 系统 / 일반 RAG 시스템 vs 제안 시스템

**一般 RAG 的工作方式**（以 Lewis et al. 2020 为代表）：
- 用户提问 → 检索相关文档 → 拼接后送入 LLM 生成答案
- 单文本路径、单轮检索
- 生成的答案与证据之间关系不明确

**일반 RAG의 작동 방식** (Lewis et al. 2020 대표):
- 사용자 질문 → 관련 문서 검색 → 이어 붙여 LLM에 입력 → 답변 생성
- 단일 텍스트 경로, 단일 라운드 검색
- 생성된 답변과 증거 간 관계가 불분명

**本系统的区别（定性）**：
1. **问题规划层 (Question Planning)**：不是直接用评论作为查询，而是通过 LLM 将评论方面分解为三种证据意图的检索问题（文本支持 / 视觉确认 / 跨模态解析），使每个查询都有明确的证据目标
2. **双路独立检索**：文本路径（商品描述文本）和图像路径（商品图片）分别召回，然后用跨模态一致性约束结合——而不是把所有模态混入同一向量空间
3. **多轮精排**：粗召回 → 跨模态重排序 → 证据缓存，每一步都可独立评估和消融
4. **Claim 级归因**：每个报告 claim 明确标注支持它的证据对象和证据状态（supported / partial / unsupported / contradicted）
5. **结构化 Schema 约束**：输出受 Pydantic schema 约束，不是开放式文本生成

**본 시스템의 차이점 (정성적)**:
1. **질문 계획 계층 (Question Planning)**: 리뷰를 그대로 쿼리로 사용하지 않고, LLM을 통해 리뷰 측면을 세 가지 증거 의도(텍스트 지지/시각 확인/크로스모달 해석)의 검색 질문으로 분해하여 각 쿼리에 명확한 증거 목표를 부여
2. **듀얼 경로 독립 검색**: 텍스트 경로와 이미지 경로를 각각 회수하고 크로스모달 일관성 제약으로 결합 — 모든 모달리티를 동일 벡터 공간에 혼합하지 않음
3. **다단계 정밀 순위화**: 거친 회수 → 크로스모달 재순위화 → 증거 캐싱, 각 단계를 독립적으로 평가 및 소거 가능
4. **Claim 단위 귀속**: 각 보고서 claim에 대해 이를 지지하는 증거 객체와 증거 상태(supported/partial/unsupported/contradicted)를 명시적으로 표시
5. **구조화 Schema 제약**: 출력이 개방형 텍스트 생성이 아닌 Pydantic schema에 의해 제약됨

## 差异化总结 / 차별화 요약

| 维度 / 차원 | 已有方法 / 기존 방법 | 本系统 / 제안 시스템 |
|------------|-------------------|-------------------|
| 证据使用 / 증거 사용 | 仅评论 / 리뷰만 | 评论 + 商品文本 + 商品图片 |
| 检索方式 / 검색 방식 | 无或单路径 / 없음 또는 단일 경로 | 双路独立召回 + 跨模态结合 |
| 问题规划 / 질문 계획 | 直接用评论文本 / 리뷰 직접 사용 | LLM 将方面分解为三种证据意图的查询 |
| 结果可信度 / 결과 신뢰도 | 难以验证 / 검증 어려움 | claim 级归因 + evidence gap → 可审计 |
| 错误追踪 / 오류 추적 | 黑盒 / 블랙박스 | 四级流水线分步存储 → 精确错误定位 |
| 重复运行 / 반복 실행 | 每次从零开始 / 매번 처음부터 | 缓存 + resume → 增量分析 |
| 成果形式 / 결과 형태 | 文本段落、分类标签 / 텍스트, 분류 라벨 | 结构化 JSON/HTML 报告 + 回放记录 |

## 消融分析说明（定性） / 소거 분석 설명 (정성적)

本系统设计了 5 个消融条件，用于定性说明各模块的功能贡献：

| 消融条件 / 소거 조건 | 说明 / 설명 | 预期效果 / 예상 효과 |
|-------------------|-----------|-------------------|
| 无问题规划 (no_qp) | 直接用评论方面做查询，不分解为三种证据意图 | 检索意图不明确，可能遗漏视觉或跨模态证据 |
| 无图像路径 (no_image) | 仅文本路由，不使用商品图片 | 无法获取视觉证据，涉及外观/结构/颜色的 claim 缺少支持 |
| 无重排序 (no_rerank) | 仅粗召回，不做精细排序 | 低质量证据混入，导致更多不确定性 |
| 无归因 (no_attribution) | 生成报告但不绑定证据 | 无法追溯结论来源，降低可信度 |
| 无消融 (full_system) | 完整系统：问题规划 + 双路检索 + 重排 + 归因 | 证据意图明确、多模态覆盖、高质量排序、结论可追溯 |

> **核心设计原则**：完整系统的目标是让每个 claim 都有明确的证据支持、可追溯的来源、以及可审计的中间过程。消融条件验证了各模块对这一目标的必要性。
> **핵심 설계 원칙**: 완전한 시스템의 목표는 모든 claim이 명확한 증거 지지, 추적 가능한 출처, 감사 가능한 중간 과정을 갖는 것입니다. 소거 조건은 각 모듈이 이 목표에 필수적임을 검증합니다.

## 对照基线说明 / 대조군 Baseline 설명

本系统实现了三个对照基线，用于定性对比设计思路的差异。这些基线基于论文描述在我们的代码框架中适配实现，使用相同的 LLM 和检索后端，确保公平比较。

본 시스템은 세 가지 대조군 baseline을 구현하여 설계 사고의 차이를 정성적으로 비교합니다. 이 baseline은 논문 설명에 따라 본 시스템의 코드 프레임워크에 적응하여 구현되었으며, 동일한 LLM과 검색 백엔드를 사용하여 공정한 비교가 가능합니다.

### Lewis et al. 2020 — 标准 RAG / 표준 RAG

标准检索增强生成方法。用户查询 → 检索相关文档 → 拼接上下文 → LLM 生成答案。

在本系统的对照实现中：直接将评论方面作为查询，在商品文本中检索后生成报告。无多模态处理、无问题规划、无重排序、无 claim 归因。

표준 검색 증강 생성 방법. 사용자 쿼리 → 관련 문서 검색 → 컨텍스트 병합 → LLM 답변 생성.

본 시스템의 대조 구현에서는: 리뷰 측면을 직접 쿼리로 사용하여 상품 텍스트에서 검색 후 보고서를 생성. 멀티모달 처리, 질문 계획, 재순위화, claim 귀속 없음.

**定性差异**：标准 RAG 生成开放式文本，无法确保每个结论都有明确证据；本系统通过问题规划和证据约束确保每个 claim 可追溯。

**정성적 차이**: 표준 RAG는 개방형 텍스트를 생성하여 각 결론이 명확한 증거를 갖는다는 것을 보장할 수 없음. 본 시스템은 질문 계획과 증거 제약을 통해 모든 claim의 추적 가능성을 보장.

### JARVIS — 证据图 + LLM 裁决 / 증거 그래프 + LLM 판결

基于证据图的方法。构建评论意见与证据之间的关系图，由 LLM 裁决冲突意见。

在本系统的对照实现中：构建简单的证据图文本表示，让 LLM 生成结构化报告。

증거 그래프 기반 방법. 리뷰 의견과 증거 간의 관계 그래프를 구축하고 LLM이 충돌 의견을 판결.

본 시스템의 대조 구현에서는: 간단한 증거 그래프 텍스트 표현을 구축하고 LLM이 구조화 보고서를 생성.

**定性差异**：JARVIS 通过图结构处理冲突，但缺乏多模态检索和证据约束；本系统通过双路检索和 claim 归因实现更细粒度的证据关联。

**정성적 차이**: JARVIS는 그래프 구조로 충돌을 처리하지만 멀티모달 검색과 증거 제약이 부족함. 본 시스템은 듀얼 경로 검색과 claim 귀속을 통해 더 세밀한 증거 연관성을 실현.

### VeriCite — 三阶段引用验证 / 3단계 인용 검증

三阶段生成方法。第一阶段生成初始报告并标注引用 → 第二阶段验证并去除 unsupported claim → 第三阶段润色。

在本系统的对照实现中：三阶段流水线生成结构化报告。

3단계 생성 방법. 1단계: 초기 보고서 생성 및 인용 표시 → 2단계: 검증하여 unsupported claim 제거 → 3단계: 다듬기.

본 시스템의 대조 구현에서는: 3단계 파이프라인으로 구조화 보고서를 생성.

**定性差异**：VeriCite 是后验验证，先生成再过滤；本系统是前验约束，先生成检索问题再找证据，再基于证据生成报告，从源头上减少 unsupported claim。

**정성적 차이**: VeriCite는 사후 검증(먼저 생성한 후 필터링). 본 시스템은 사전 제약(먼저 검색 질문을 생성하고 증거를 찾은 후, 증거를 바탕으로 보고서를 생성)하여 unsupported claim을 근원적으로 줄임.

## 关键结论 / 핵심 결론

> 本系统与普通评论分析器的核心差异不在于"做得更好"，而在于**设计范式不同**：
> 1. 从"单步摘要"到"多步证据对齐"
> 2. 从"文本-only"到"多模态证据检索"
> 3. 从"黑盒输出"到"claim 级归因与审计"
> 4. 从"一次性分析"到"可重现、可增量、可反馈"

> 본 시스템과 일반 리뷰 분석기의 핵심 차이는 "더 잘함"이 아니라 **설계 패러다임이 다름**:
> 1. "단일 단계 요약"에서 "다단계 증거 정렬"로
> 2. "텍스트만"에서 "멀티모달 증거 검색"으로
> 3. "블랙박스 출력"에서 "claim 단위 귀속 및 감사"로
> 4. "일회성 분석"에서 "재현 가능, 증분 가능, 피드백 가능"으로
