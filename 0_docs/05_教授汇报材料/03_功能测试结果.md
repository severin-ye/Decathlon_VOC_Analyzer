## 实验设计 / 실험 설계

### 实验条件（8 个）/ 실험 조건 (8개)

系统设计了 **5 个消融条件** 和 **3 个对照基线**，用于说明各模块的功能贡献和设计差异：

| # | 조건 (条件 ID) | 설명 (说明) |
|---|---------------|-----------|
| 1 | `full_system` | **完整系统**：问题规划 + 文本+图像双路召回 + 重排序 + claim 归因 |
| 2 | `ablation_no_qp` | **消融：无问题规划** — 直接用评论方面做查询 |
| 3 | `ablation_no_image` | **消融：无图像路径** — 仅文本路由 |
| 4 | `ablation_no_rerank` | **消融：无重排序** — 仅粗召回 |
| 5 | `ablation_no_attribution` | **消融：无归因** — 生成报告但不绑定证据 |
| 6 | `control_lewis2020` | **对照：Lewis 2020 RAG** — 标准检索增强生成基线 |
| 7 | `control_jarvis` | **对照：JARVIS** — 证据图 + LLM 裁决基线 |
| 8 | `control_vericite` | **对照：VeriCite** — 三阶段引用验证基线 |

시스템은 **5개의 소거 조건**과 **3개의 대조군 baseline**을 설계하여 각 모듈의 기능 기여와 설계 차이를 설명합니다.

### 评价维度 / 평가 차원

当前阶段主要进行**功能级定性对比和输出结果差异分析**，而非完整的定量性能评估。评价维度包括：

| 지표 (指标) | 설명 (说明) |
|------------|-----------|
| `claim_count` | 生成的 claim 总数 / 생성된 claim 총수 |
| `supported_claims` | 有明确证据支持的 claim 数 / 증거로 뒷받침된 claim 수 |
| **Claim Support Rate** | supported_claims / claim_count — 反映证据支持程度 |
| `aspect_count` | 提取的评论方面数 / 추출된 리뷰 측면 수 |
| `duration_seconds` | 运行耗时 / 실행 소요 시간 |

> **주의사항**: 현재 단계는 정량 지표보다는 **기능 단위 비교와 출력 결과의 차이**를 중심으로 테스트했습니다. 즉, "어떤 모듈이 있을 때와 없을 때 결과가 어떻게 다른가"를 정성적으로 분석합니다.

## 实验结果说明 / 실험 결과 설명

### 消融实验结果（定性） / 소거 실험 결과 (정성적)

系统对 backpack 品类的两个商品（backpack_071, backpack_060）运行了全部 8 个条件。以下是对结果的**定性分析**（不涉及具体数值）：

시스템은 backpack 카테고리의 두 상품(backpack_071, backpack_060)에 대해 모든 8개 조건을 실행했습니다. 다음은 결과의 **정성적 분석**입니다(구체적 수치 미포함):

#### 1. 完整系统 (full_system)

**设计特征**：问题规划 + 文本+图像双路检索 + 重排序 + claim 归因

**定性效果**：
- 每个 claim 都有明确的证据支持
- 文本和图像证据均被有效利用
- 报告中的结论可追溯至具体评论、商品文本或商品图片
- evidence gap 被明确标注，不会编造无证据的结论

**설계 특징**: 질문 계획 + 텍스트+이미지 듀얼 경로 검색 + 재순위화 + claim 귀속

**정성적 효과**:
- 모든 claim에 명확한 증거 지지가 있음
- 텍스트와 이미지 증거가 모두 효과적으로 활용됨
- 보고서의 결론이 구체적 리뷰, 상품 텍스트, 상품 이미지로 추적 가능
- evidence gap이 명시적으로 표시되어 증거 없는 결론을 생성하지 않음

#### 2. 无问题规划 (ablation_no_qp)

**设计差异**：跳过 Question Planning，直接用评论方面文本做检索查询

**定性效果**：
- 检索意图不够明确 — "容量小" 这个方面直接作为查询，缺乏"文本支持/视觉确认/跨模态解析"的分解
- 可能遗漏需要视觉证据支持的 claim
- 相比完整系统，证据支持的完整性和精确性有所下降

**설계 차이**: Question Planning을 걱너뛰고 리뷰 측면 텍스트를 직접 검색 쿼리로 사용

**정성적 효과**:
- 검색 의도가 명확하지 않음 — "용량이 작다"라는 측면을 직접 쿼리로 사용하여 "텍스트 지지/시각 확인/크로스모달 해석"의 분해가 없음
- 시각 증거가 필요한 claim을 놓칠 수 있음
- 완전한 시스템에 비해 증거 지지의 완전성과 정확성이 감소

#### 3. 无图像路径 (ablation_no_image)

**设计差异**：仅使用文本路径检索，不使用商品图片

**定性效果**：
- 无法获取视觉证据（如外观、结构、颜色、收纳形态）
- 涉及视觉特征的 claim 缺少支持，可能被迫标记为 evidence gap
- 文本证据仍可支持大部分 claim，但多模态交叉验证能力丧失

**설계 차이**: 텍스트 경로만 사용, 상품 이미지 미사용

**정성적 효과**:
- 시각 증거(외관, 구조, 색상, 수납 형태)를 획득할 수 없음
- 시각적 특징이 관련된 claim에 지지가 부족하여 evidence gap으로 표시될 수 있음
- 텍스트 증거로 대부분의 claim을 지지할 수 있지만, 멀티모달 교차 검증 기능 상실

#### 4. 无重排序 (ablation_no_rerank)

**设计差异**：粗召回后不做精细排序，直接使用召回结果

**定性效果**：
- 低质量证据混入候选集合
- claim 数量可能增加，但 supported 比例下降
- 证据的相关性和一致性未经精细筛选

**설계 차이**: 거친 회수 후 정밀 정렬 없이 회수 결과 직접 사용

**정성적 효과**:
- 저품질 증거가 후보 집합에 혼입됨
- claim 수가 증가할 수 있지만 supported 비율이 감소
- 증거의 관련성과 일관성이 정밀 필터링되지 않음

#### 5. 无归因 (ablation_no_attribution)

**设计差异**：生成报告但不将 claim 绑定到具体证据

**定性效果**：
- claim 数量为 0 — 因为归因机制是 claim 生成的内置约束
- 证明"证据约束"不是可选功能，而是核心生成流程的一部分
- 移除归因后报告不可生成，说明本系统的设计将可追溯性嵌入核心

**설계 차이**: 보고서를 생성하되 claim을 구체적 증거에 바인딩하지 않음

**정성적 효과**:
- claim 수가 0 — 귀속 메커니즘이 claim 생성의 내장 제약이기 때문
- "증거 제약"이 선택적 기능이 아니라 핵심 생성 흐름의 일부임을 증명
- 귀속 제거 시 보고서가 생성되지 않음 — 본 시스템의 설계가 추적 가능성을 핵심에 내장했음을 보여줌

### 对照基线对比（定性） / 대조군 Baseline 비교 (정성적)

#### Lewis 2020 RAG 基线

**设计特征**：标准单文本路径 RAG。用户查询 → 检索文档 → 拼接上下文 → LLM 生成

**与本系统的定性差异**：
- **单路径 vs 双路径**：仅文本检索，无图像证据
- **无问题规划**：直接使用评论文本做查询，缺乏证据意图分解
- **开放式生成**：输出不受 schema 约束，可能生成无证据支持的 claim
- **无归因**：无法追溯结论来源

**설계 특징**: 표준 단일 텍스트 경로 RAG. 사용자 쿼리 → 문서 검색 → 컨텍스트 병합 → LLM 생성

**본 시스템과의 정성적 차이**:
- **단일 경로 vs 듀얼 경로**: 텍스트 검색만 있고 이미지 증거 없음
- **질문 계획 없음**: 리뷰 텍스트를 직접 쿼리로 사용하여 증거 의도 분해가 없음
- **개방형 생성**: 출력이 schema 제약이 없어 증거 없는 claim을 생성할 수 있음
- **귀속 없음**: 결론의 출처를 추적할 수 없음

#### JARVIS 基线

**设计特征**：构建证据图，由 LLM 裁决冲突意见后生成报告

**与本系统的定性差异**：
- **图结构 vs 流水线**：JARVIS 用图处理冲突，本系统用多步流水线处理证据对齐
- **无多模态检索**：JARVIS 的证据图基于已有文本证据，不主动检索商品图片
- **裁决 vs 约束**：JARVIS 是 LLM 裁决冲突，本系统是证据约束生成

**설계 특징**: 증거 그래프를 구축하고 LLM이 충돌 의견을 판결한 후 보고서를 생성

**본 시스템과의 정성적 차이**:
- **그래프 구조 vs 파이프라인**: JARVIS는 충돌 처리에 그래프를 사용하고, 본 시스템은 다단계 파이프라인으로 증거 정렬을 처리
- **멀티모달 검색 없음**: JARVIS의 증거 그래프는 기존 텍스트 증거에 기반하고, 상품 이미지를 능동적으로 검색하지 않음
- **판결 vs 제약**: JARVIS는 LLM이 충돌을 판결하고, 본 시스템은 증거 제약 생성을 사용

#### VeriCite 基线

**设计特征**：三阶段生成。先生成 → 再验证去 Unsupported → 最后润色

**与本系统的定性差异**：
- **后验验证 vs 前验约束**：VeriCite 是生成后过滤，本系统是生成前检索证据
- **无多模态**：VeriCite 仅处理文本引用验证
- **无问题规划**：无证据意图分解步骤

**설계 특징**: 3단계 생성. 먼저 생성 → unsupported 제거 검증 → 마지막으로 다듬기

**본 시스템과의 정성적 차이**:
- **사후 검증 vs 사전 제약**: VeriCite는 생성 후 필터링이고, 본 시스템은 생성 전 증거 검색
- **멀티모달 없음**: VeriCite는 텍스트 인용 검증만 처리
- **질문 계획 없음**: 증거 의도 분해 단계가 없음

## 关键发现 / 핵심 발견

### 1. 消融实验验证了各模块的必要性 / 소거 실험이 각 모듈의 필요성을 검증

从定性结果可以看出：
- **问题规划 (QP)**：移除后检索意图不明确，影响证据支持的完整性
- **图像路径**：移除后视觉证据缺失，影响涉及外观/结构 claim 的支持
- **重排序**：移除后低质量证据混入，降低结果可信度
- **归因**：移除后报告不可生成，证明归因是系统的核心设计约束而非可选功能

정성적 결과에서 다음을 확인할 수 있음:
- **질문 계획(QP)**: 제거 시 검색 의도가 불분명해져 증거 지지의 완전성에 영향
- **이미지 경로**: 제거 시 시각 증거가 부재되어 외관/구조 관련 claim 지지에 영향
- **재순위화**: 제거 시 저품질 증거가 혼입되어 결과 신뢰도가 감소
- **귀속**: 제거 시 보고서가 생성되지 않아 귀속이 시스템의 핵심 설계 제약임을 증명(선택적 기능이 아님)

### 2. 对照基线体现了设计范式的差异 / 대조군 baseline이 설계 패러다임의 차이를 보여줌

- **Lewis 2020 (标准 RAG)**：单路径、开放式生成、无证据约束 → 代表"传统 RAG"范式
- **JARVIS (证据图)**：图结构处理冲突、LLM 裁决 → 代表"后处理冲突"范式
- **VeriCite (三阶段验证)**：生成后验证过滤 → 代表"后验质量控制"范式
- **本系统**：问题规划 → 双路检索 → 重排序 → 证据约束生成 → 代表"前验证据对齐"范式

### 3. 当前阶段的定位 / 현재 단계의 위치

> **当前阶段主要进行功能级对比和输出结果差异分析，而不是完整的定量性能评估。**
> > 현재 단계는 완전한 정량 성능 평가가 아닌 **기능 수준의 비교와 출력 결과의 차이 분석**입니다.

消融实验和对照基线的目的是：
1. **验证设计**：证明每个模块在系统设计中的必要性
2. **展示差异**：定性说明本系统与传统方法在范式上的不同
3. **功能对比**：说明"有"和"没有"某项技术时，输出结果在结构和可信度上的差异

소거 실험과 대조군 baseline의 목적은:
1. **설계 검증**: 각 모듈이 시스템 설계에서 필수적임을 증명
2. **차이 제시**: 본 시스템과 전통적 방법의 패러다임 차이를 정성적으로 설명
3. **기능 비교**: 특정 기술의 "유무"에 따라 출력 결과의 구조와 신뢰도가 어떻게 다른지 설명

## 注意事项 / 주의사항

- 当前实验为 **功能级定性对比验证**，旨在展示各模块的功能贡献和设计差异
- 8 个条件 × 15 商品 = 120 次运行计划。当前已完成部分运行，部分因缺少评论抽取中间产物而失败（需先进行 Stage 2 的评论方面抽取）
- 如需完整实验报告，建议先对目标商品执行一次完整分析以生成中间产物，再运行实验矩阵
- 현재 실험은 **기능 수준의 정성적 비교 검증**으로, 각 모듈의 기능 기여와 설계 차이를 보여주기 위함
- 8개 조건 × 15개 상품 = 120회 실행 계획. 일부는 리뷰 측면 추출 중간 산출물 부재로 실패 (Stage 2를 먼저 실행 필요)
- 전체 보고가 필요하면 대상 상품에 대해 먼저 전체 분석을 1회 실행해 중간 산출물을 생성한 후 실험 매트릭스를 실행할 것
