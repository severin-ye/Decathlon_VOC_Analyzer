## 实验设计

### 实验条件（8 个）

系统设计了 **5 个消融条件** 和 **3 个对照基线**，用于说明各模块的功能贡献和设计差异：

| # | 条件 ID | 说明 |
|---|---------------|-----------|
| 1 | `full_system` | **完整系统**：问题规划 + 文本+图像双路召回 + 重排序 + claim 归因 |
| 2 | `ablation_no_qp` | **消融：无问题规划** — 直接用评论方面做查询 |
| 3 | `ablation_no_image` | **消融：无图像路径** — 仅文本路由 |
| 4 | `ablation_no_rerank` | **消融：无重排序** — 仅粗召回 |
| 5 | `ablation_no_attribution` | **消融：无归因** — 生成报告但不绑定证据 |
| 6 | `control_lewis2020` | **对照：Lewis 2020 RAG** — 标准检索增强生成基线 |
| 7 | `control_jarvis` | **对照：JARVIS** — 证据图 + LLM 裁决基线 |
| 8 | `control_vericite` | **对照：VeriCite** — 三阶段引用验证基线 |

### 评价维度

当前阶段主要进行**功能级定性对比和输出结果差异分析**，而非完整的定量性能评估。评价维度包括：

| 指标 | 说明 |
|------------|-----------|
| `claim_count` | 生成的 claim 总数 |
| `supported_claims` | 有明确证据支持的 claim 数 |
| **Claim Support Rate** | supported_claims / claim_count — 反映证据支持程度 |
| `aspect_count` | 提取的评论方面数 |
| `duration_seconds` | 运行耗时 |

> **注意**：当前阶段以**功能单元对比和输出结果差异**为中心进行测试，即定性分析"有/无某个模块时结果有何不同"。

## 实验结果说明

### 消融实验结果（定性）

系统对 backpack 品类的两个商品（backpack_071, backpack_060）运行了全部 8 个条件。以下是对结果的**定性分析**：

#### 1. 完整系统 (full_system)

**设计特征**：问题规划 + 文本+图像双路检索 + 重排序 + claim 归因

**定性效果**：
- 每个 claim 都有明确的证据支持
- 文本和图像证据均被有效利用
- 报告中的结论可追溯至具体评论、商品文本或商品图片
- evidence gap 被明确标注，不会编造无证据的结论

#### 2. 无问题规划 (ablation_no_qp)

**设计差异**：跳过 Question Planning，直接用评论方面文本做检索查询

**定性效果**：
- 检索意图不够明确 — "容量小" 这个方面直接作为查询，缺乏"文本支持/视觉确认/跨模态解析"的分解
- 可能遗漏需要视觉证据支持的 claim
- 相比完整系统，证据支持的完整性和精确性有所下降

#### 3. 无图像路径 (ablation_no_image)

**设计差异**：仅使用文本路径检索，不使用商品图片

**定性效果**：
- 无法获取视觉证据（如外观、结构、颜色、收纳形态）
- 涉及视觉特征的 claim 缺少支持，可能被迫标记为 evidence gap
- 文本证据仍可支持大部分 claim，但多模态交叉验证能力丧失

#### 4. 无重排序 (ablation_no_rerank)

**设计差异**：粗召回后不做精细排序，直接使用召回结果

**定性效果**：
- 低质量证据混入候选集合
- claim 数量可能增加，但 supported 比例下降
- 证据的相关性和一致性未经精细筛选

#### 5. 无归因 (ablation_no_attribution)

**设计差异**：生成报告但不将 claim 绑定到具体证据

**定性效果**：
- claim 数量为 0 — 因为归因机制是 claim 生成的内置约束
- 证明"证据约束"不是可选功能，而是核心生成流程的一部分
- 移除归因后报告不可生成，说明本系统的设计将可追溯性嵌入核心

### 对照基线对比（定性）

#### Lewis 2020 RAG 基线

**设计特征**：标准单文本路径 RAG。用户查询 → 检索文档 → 拼接上下文 → LLM 生成

**与本系统的定性差异**：
- **单路径 vs 双路径**：仅文本检索，无图像证据
- **无问题规划**：直接使用评论文本做查询，缺乏证据意图分解
- **开放式生成**：输出不受 schema 约束，可能生成无证据支持的 claim
- **无归因**：无法追溯结论来源

#### JARVIS 基线

**设计特征**：构建证据图，由 LLM 裁决冲突意见后生成报告

**与本系统的定性差异**：
- **图结构 vs 流水线**：JARVIS 用图处理冲突，本系统用多步流水线处理证据对齐
- **无多模态检索**：JARVIS 的证据图基于已有文本证据，不主动检索商品图片
- **裁决 vs 约束**：JARVIS 是 LLM 裁决冲突，本系统是证据约束生成

#### VeriCite 基线

**设计特征**：三阶段生成。先生成 → 再验证去 Unsupported → 最后润色

**与本系统的定性差异**：
- **后验验证 vs 前验约束**：VeriCite 是生成后过滤，本系统是生成前检索证据
- **无多模态**：VeriCite 仅处理文本引用验证
- **无问题规划**：无证据意图分解步骤

## 功能级对比总结

| 条件 | 核心差异 | 预期效果 |
|------------|---------------------|---------------------|
| **完整系统** | 四阶段流水线完整运行 | 证据意图明确、多模态覆盖、高质量排序、结论可追溯 |
| **无问题规划** | 跳过证据意图分解 | 检索目标模糊，可能遗漏视觉/跨模态证据 |
| **无图像路径** | 仅文本检索 | 视觉特征相关的 claim 缺少支持 |
| **无重排序** | 跳过精细排序 | 低质量证据混入，不确定性增加 |
| **无归因** | 不绑定证据来源 | 报告不可生成，证明归因是核心约束 |
| **Lewis 2020** | 标准单路径 RAG | 开放式生成，无证据约束，无多模态 |
| **JARVIS** | 证据图 + LLM 裁决 | 处理冲突但缺乏多模态检索和证据约束 |
| **VeriCite** | 三阶段后验验证 | 生成后过滤，非前验证据约束 |

## 关键发现

### 1. 消融实验验证了各模块的必要性

从定性结果可以看出：
- **问题规划 (QP)**：移除后检索意图不明确，影响证据支持的完整性
- **图像路径**：移除后视觉证据缺失，影响涉及外观/结构 claim 的支持
- **重排序**：移除后低质量证据混入，降低结果可信度
- **归因**：移除后报告不可生成，证明归因是系统的核心设计约束而非可选功能

### 2. 对照基线体现了设计范式的差异

- **Lewis 2020 (标准 RAG)**：单路径、开放式生成、无证据约束 → 代表"传统 RAG"范式
- **JARVIS (证据图)**：图结构处理冲突、LLM 裁决 → 代表"后处理冲突"范式
- **VeriCite (三阶段验证)**：生成后验证过滤 → 代表"后验质量控制"范式
- **本系统**：问题规划 → 双路检索 → 重排序 → 证据约束生成 → 代表"前验证据对齐"范式

### 3. 当前阶段的定位

> **当前阶段主要进行功能级对比和输出结果差异分析，而不是完整的定量性能评估。**

消融实验和对照基线的目的是：
1. **验证设计**：证明每个模块在系统设计中的必要性
2. **展示差异**：定性说明本系统与传统方法在范式上的不同
3. **功能对比**：说明"有"和"没有"某项技术时，输出结果在结构和可信度上的差异
